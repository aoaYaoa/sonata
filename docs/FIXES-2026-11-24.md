## 前端登录入口隐藏（2026-11-25）

**问题**：口令从 8 位 `admin123` 提升到 24 位随机串后，用户在 iPhone 上无法手输登录。

**做法**：登录不再暴露给用户，改为客户端静默认证。

1. `lib/services/auth_service.dart` 新增 `_defaultPassword`，用 `String.fromEnvironment('SOLARA_PASS')` 在构建期注入。源码里不留默认值——仓库公开，口令写进代码等于公开（见本节末尾的注意）。
2. `restoreSession()` 在本地无 token 时直接用内置口令调 `/api/login` 换 token，成功后 `isAuthed = true`，用户直接进主界面。
3. `autoRelogin()` 区分游客态与失效态：本地本就没有 token 时不再把用户拽回登录页，避免一次读操作失败就弹登录。
4. `login_screen.dart` 重写为「连接失败」兜底页，只剩重试按钮，无口令输入框。只有后端不可达或口令被改才会出现。

**构建命令**（口令需与服务器 `.env` 的 `APP_PASSWORD` 一致）：

```bash
cd frontend
export PATH="/opt/homebrew/lib/ruby/gems/3.4.0/bin:/Users/aay/flutter/bin:$PATH"
flutter build ios --release --dart-define=SOLARA_PASS='<服务器 .env 里的 APP_PASSWORD>'
xcrun devicectl device install app --device <UDID> build/ios/iphoneos/Runner.app
```

**注意**：口令是编译进包的明文常量，改服务器口令必须重新构建安装，否则应用会落到兜底页。这是「隐藏入口」的代价——真正的密钥托管需要服务端签发长期 token，不在本次范围。

**不要**把口令写进源码默认值或文档示例：仓库是公开的（`aoaYaoa/sonata`），一旦提交就永久留在 git 历史里，任何人都能拿它登录线上后端。口令只通过构建参数传入，保存在构建机的环境变量或本地脚本里（已被 `.gitignore` 排除）。

- 酷狗：判定看 `privilege` 而非 `pay_type`。`privilege=0/8` 都能拿 128k mp3，
  `privilege=10` 才是空 url。注意 `pay_type=3` 的曲目很多 `privilege` 是 8，
  按 `pay_type` 判会把可播的曲子误标成会员曲。

**已知限制**

- QQ 会员曲、酷狗 `privilege>=10` 的曲目在匿名态拿不到流，前端会收到 404。
  要解锁需在 `.env` 配 `QQ_COOKIE` / `KUGOU_COOKIE` 并在取流时带上
  `g_tk = hash33(musickey, 5381)`（`qqSignGTK` 已实现但未接线）。
- 酷狗的 `br` 参数不生效，音质由 hash 决定；搜索结果里的 `320hash`/`sqhash`
  已存进 `alt_ids`，前端换音质时要用对应 hash 而不是传 br。
- 两家都不校验媒体流 Referer（实测 `sharefs.kugou.com` 与 `aqqmusic.tc.qq.com`
  对空 Referer、空 UA 都返回 206），但仍保留 Referer 以防节点策略变化。
