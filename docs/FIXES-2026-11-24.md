## 二、P0 修复

### P0-1 JWT 默认密钥可伪造 admin 令牌

`backend/pkg/utils/jwt/jwt.go`

- `weakSecretPlaceholders`（精确 map）改为 `weakSecretPatterns`（子串匹配）＋ `strings.Contains(lower, pattern)`。原实现只拦 `your-secret-key-change-in-production`，而 `.env` 里写的是 `your-jwt-secret-key-change-in-production`——差三个字母，实测可自签 token 打通 `GET /api/admin/users`。
- 模式表：`change-in-production`、`change-me`、`changeme`、`change_me`、`your-secret`、`your-jwt`、`your-api-signing`、`placeholder`、`insecure`、`test-secret`、`dev-secret`、`default-secret`。刻意排除 `your-`/`example`/`todo` 这类过宽片段，否则正常密钥会被误杀。
- 新增 `SecretFingerprint(secret) string`（sha256 前 8 位 hex），`main.go` 启动时打印指纹，便于多环境核验密钥一致性又不泄露密钥本体。

**实测**：`JWT_SECRET=your-jwt-secret-key-change-in-production` → `panic: JWT_SECRET 含弱密钥片段 "change-in-production"`。

### P0-2 `/proxy` 命令注入 → RCE

`backend/internal/handlers/source_youtube.go`、`proxy.go`

- 删除 `execShell(cmd string)`（`exec.CommandContext(ctx, "sh", "-c", cmd)`），改为 `runYtDlp(ctx context.Context, args ...string)`：`exec.LookPath("yt-dlp")` + `exec.CommandContext(ctx, bin, args...)`，60s 超时，stderr 只保留末 400 字符。
- 新增 `youtubeVideoIDPattern = ^[A-Za-z0-9_-]{11}$`、`bilibiliBVIDPattern = ^BV[0-9A-Za-z]{10}$`，在 `youtubeGetAudioUrl`/`youtubeGetVideoUrl`/`BilibiliPlayUrl` 入口白名单校验。
- `youtubeSearch` 不再把 keyword 拼进命令串（去掉 `strings.ReplaceAll(keyword, "'", "")` 这种打补丁式过滤），改 `append(args, fmt.Sprintf("ytsearch%d:%s official music video", ...))`。
- 新增 `errInvalidVideoID` sentinel + `statusForSourceError(err)`：调用方输入非法回 400，上游失败回 502（历史实现一律 502，把客户端错误误导成上游故障）。
- `--cookies` 改为仅在 cookie 文件存在时追加（原先无条件传，无 cookie 时 yt-dlp 直接报错退出）。

**实测**：`/proxy?source=youtube&types=url&id=x';id>/tmp/inj5.txt;'` → `{"error":"invalid video id"}` HTTP 400，文件未生成（修复前以 `uid=501(aay)` 执行成功）；合法 11 位 id `dQw4w9WgXcQ` 正常返回 googlevideo 播放地址。

### P0-3 `APP_PASSWORD` 为空时认证完全失效

`backend/internal/config/config.go`、`handlers/auth.go`

- 新增 `Config.Validate()`，收集**全部**问题后统一 `panic`：`APP_PASSWORD` 为空、长度 `< MinAppPasswordLength(16)`、`CORS_ORIGIN` 含 `*`。
- `Login`：口令空 → 503 `"服务未正确配置"`；比较改用 `subtle.ConstantTimeCompare`。
- `isAuthed`：口令空 → `return false`（原 `return true`）；cookie 比较同样改常量时间。

**实测**：`APP_PASSWORD=''` → `- APP_PASSWORD 未配置。空口令会导致认证完全失效，拒绝启动`；`admin123` → `长度 8 < 16`；`CORS_ORIGIN='*'` → `为通配符 *，请改为显式域名`。

### P0-4 弱口令 + 零防爆破 + 明文落盘

- `backend/internal/middlewares/login_guard.go`（新建）：按 IP 的失败计数 + 锁定窗口（默认 5 次 / 15 分钟 / 15 分钟统计窗口 / 10 分钟清理）。命中锁定返回 429 + `Retry-After`。`LoginGuard.Middleware()` 依据 `c.Writer.Status()` 自动记账（200→成功清零，401→失败累加）。
- `routes.go`：`/api/login` 单独挂 `RateLimit(0.5, 5)` + `NewLoginGuard().Middleware()`。
- `frontend/lib/services/auth_service.dart`：**删掉明文口令落盘**。`String? _sessionPassword` 只在内存，进程重启即失效（fail-closed）；`logout()` 额外 `prefs.remove('user_password')` 清理旧版残留。

**实测**：5 次错误口令后第 6 次起 429（含正确口令），`Retry-After` 生效。

### P0-5 `/imgproxy` 无鉴权无白名单 SSRF

`backend/internal/handlers/urlguard.go`（新建）、`proxy.go`

- `validateProxyTarget(ctx, rawURL, allowlist)`：协议只允许 `http`/`https`；host 必须命中白名单；域名解析结果**全部**必须非内网（防 DNS rebinding）。
- `hostInAllowlist`：`"kuwo.cn"` 精确、`".kuwo.cn"` 子域；先 `ToLower` + 去尾点。
- `isDisallowedIP`：Loopback / Private / LinkLocal / Multicast / Unspecified / `v4[0]==0`。
- `safeDialControl` 挂在 `net.Dialer.Control`，拨号前再校验一次实际 IP（防校验后被重解析）。
- `newGuardedHTTPClient(timeout)`：`timeout<=0` 关闭整体超时（流媒体需要）。
- `ImgProxy`：白名单配置 `IMG_PROXY_ALLOWED_HOSTS`（默认 `.music.126.net,.126.net,.127.net,.netease.com`），10s 超时，响应必须 `image/` 前缀，`Content-Type` 不符 → 502，`ContentLength > 10 MiB` → 413，`io.LimitReader` 截断。

**实测**：`?url=http://127.0.0.1:8080/health` / `169.254.169.254` / `file:///etc/passwd` / `example.com` → 全 400 `{"error":"目标地址不受支持"}`。
